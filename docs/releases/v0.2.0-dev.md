# Gantry Core v0.2.0 development line

The v0.2.0 development line extracts the clustering behavior proven by Watchpost CP9-CP17 without centralizing Watchpost persistence or policy.

## Shared cluster API

`github.com/gantry-tools/gantry-core/cluster` now defines:

- protocol-versioned node identities, capabilities and membership vocabulary;
- invitation, join, approval, rejection, rotation, revocation, removal and re-pair lifecycle contracts;
- node fingerprints and credential generation/validation rules;
- canonical HMAC request signatures, payload limits and clock-skew rules;
- `local`, `node:<id>`, `members` and `all` target selectors;
- bounded parallel fan-out with deterministic per-node partial results;
- the common `cluster` CLI command family;
- common member, invitation, audit and overview presentation contracts.

Consumers own persistence, authorization, audit storage, route registration, product-specific operations and visual design. The package does not provide consensus, database replication, shared human accounts or configuration propagation.

## Compatibility

Cluster protocol version `1` remains the Watchpost Phase 2 wire semantic. The Watchpost CP25 rebase keeps its existing `X-Watchpost-*` HTTP headers while delegating canonical signing to Gantry Core, avoiding a wire-format break during extraction.

The API is intentionally storage-neutral. Phase 4 consumers should adapt their own persistence rather than importing Watchpost schema assumptions.
